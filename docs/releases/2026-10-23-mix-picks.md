# Mix rooms, stage П4 — hero picks: release note

A mix's hero room can pick heroes as well as ban them (spec §10, §11). Three new presets, all `mix_eligible`:
`lol_draft` (LoL — side pick, then the tournament order of bans and picks, each pick by the team's next player in
position order), `lol_captains` (LoL — the same with captains picking for the team, then an assignment step) and
`deadlock_bans_pick` (Deadlock — the four bans, then everyone picks at once). The mix header and the hosts' per-game
defaults offer them. The tournament rules editor's catalog lists them too, but a tournament config holding one is
refused on save (`mix_only`). A hero is unique in a match (`DisciplineSpec.character_uniqueness`: Overwatch `team`,
LoL and Deadlock `match`; hero picks need `match`). Open simultaneous picks are first-lock-wins. Blind picks are not
supported.

The player, their captain or a host makes a member pick; only a captain or a host assigns. When a pick's clock runs
out, every member still owing one gets a random hero they may take. The heroes are matched jointly across both teams,
so each of them gets a distinct allowed hero. A timed-out assignment keeps the captain's choices that still extend to a
complete assignment and matches the rest at random.

**Fearless** (`mix.custom_game.hero_fearless`) is a header switch. A clone copies it, and there is no host default. It
keeps a player off the heroes picked for them in this mix's recorded rounds, in every lobby. The room reads the
exclusions once, when it opens, so a round undone before then frees its heroes. Fearless counts site picks only. Under
`lol_captains`, a team pick must still leave a full assignment possible. The room names each player on their pick step
and alerts both that member and their captain. The Live summary and the match history show each player's hero. Spec:
`docs/superpowers/specs/2026-10-21-mix-rooms-draft-bans-design.md` §11.6.

## Migration and deploy

One migration after `mixdraft02`: **`mixpick01`**.

- It adds `encounter.pick_ban_submission.team_member_id`, an FK to `encounter.team_member` with `ON DELETE CASCADE`. The
  column joins the unique key `uq_pick_ban_submission_step_team_attempt`, which stays NULLS NOT DISTINCT.
- It adds `encounter.pick_ban_entry.picked_for_member_id`, an FK with `ON DELETE SET NULL`.
- It adds `mix.custom_game.hero_fearless` (NOT NULL, default false).

Existing rows keep NULLs. Nothing is backfilled, and there is no new queue, route or event.

Deploy everything **from one SHA**. Run the migration first, then roll balancer-service, tournament-service, the
gateway (regenerated `schemas.json`) and the frontend. Run the pre-deploy checks below before any of it.

### Downgrade cost

Rolling `mixpick01` back destroys pick data so that pre-П4 code can read what is left:

- It deletes every `encounter.pick_ban_session` whose ruleset holds a member step or an `assign` step, running rooms
  included. Their entries and submissions cascade with them, so those matches lose their bans and picks from the match
  history.
- It deletes any other member answer (`pick_ban_submission.team_member_id IS NOT NULL`).
- It sets `mix.custom_game.hero_ban_preset` and `mix.lobby.live_ban_preset` to NULL where they name `lol_draft`,
  `lol_captains` or `deadlock_bans_pick`.
- It strips those three codes from the hosts' default presets (`balancer.user_config.hero_ban_presets`).
- It drops `hero_fearless`, which turns Fearless off in every mix, and `picked_for_member_id`.

Tournament data is untouched.

## Pre-deploy checks

Run both queries on staging or on a restored dump, never on production (`PGHOST`/`PGDATABASE` at the copy). Both
are read-only, and neither one changes any data.

**1. Deadlock uniqueness (R4-10): a stop condition.** Deadlock is declared `match` on the strength of public sources.
Any row from the first query refutes that: stop and report. The second query is the denominator; a zero there proves
nothing, so report it too.

```sql
SELECT m.id AS stats_match_id, m.encounter_id, f.entity_id AS hero_id, e.name AS hero,
       count(DISTINCT f.encounter_team_id) AS teams_with_hero
FROM stats.fact f
JOIN stats.match m  ON m.id = f.match_id
JOIN catalog.entity e ON e.id = f.entity_id
WHERE m.discipline = 'deadlock'
  AND f.entity_id IS NOT NULL
  AND f.workspace_member_id IS NOT NULL
GROUP BY m.id, m.encounter_id, f.entity_id, e.name
HAVING count(DISTINCT f.encounter_team_id) > 1;

-- denominator
SELECT count(DISTINCT m.id) FROM stats.match m
JOIN stats.fact f ON f.match_id = m.id AND f.entity_id IS NOT NULL AND f.workspace_member_id IS NOT NULL
WHERE m.discipline = 'deadlock';
```

**2. Tournament hero configs the new validator refuses (R-F6).** The query lists stored hero configs with a `pick` step
in a `team` or `none` game: every game except LoL and Deadlock, which today means Overwatch. It also lists configs with
a blind hero pick in any game. Report the ids and games. Running rooms are unaffected, because nothing re-validates a
stored config when a room opens. Any hit is a config its organizer must edit before its next save, which otherwise gets
a 422.

```sql
SELECT c.id AS pick_ban_config_id, c.tournament_id, t.discipline, c.stage_id, c.round
FROM tournament.pick_ban_config c
JOIN tournament.tournament t ON t.id = c.tournament_id
WHERE c.kind = 'hero'
  AND (
    (t.discipline NOT IN ('lol', 'deadlock')
     AND jsonb_path_exists(c.ruleset_json::jsonb, '$.phases[*].steps[*] ? (@.action == "pick")'))
    OR jsonb_path_exists(c.ruleset_json::jsonb, '$.phases[*].steps[*] ? (@.action == "pick" && @.blind == true)')
  )
ORDER BY c.id;
```

## Staging check: the manual room smoke (not run)

The manual LoL and Deadlock room smoke from the plan's Task 9 has **not** been run. Run it on staging after the deploy:

- **Deadlock, `deadlock_bans_pick` with Fearless on.** Run the four bans. A player picks on a phone, the captain picks
  for a teammate, and one player times out. Record the match. At the next Start the earlier heroes are greyed out for
  their players only. Undo the round, and they come back.
- **LoL, `lol_draft`, positions format.** The picks go top → support on each side.
- **LoL, `lol_captains`.** The captains make the team picks, then the assignment, with one captain timing out.
- **A tournament hero room** still bans as before.
