# Riot Sign-On and League of Legends native ranks: release note

This release adds sign-in and account linking with Riot (RSO). It also collects League of Legends Solo/Duo and Flex
ranks from the Riot API and uses them wherever Overwatch's native ranks are used: balancer, registration, rank overview,
profile and admin collectors. Ranks of every game now live in one `rank` schema.

One database migration ships: **`rank01`** (after `quota0003`). Deploy every backend service, the gateway (route
table and regenerated `schemas.json`) and the frontend **from one SHA, right after the migration**. Old images query
`overwatch_rank.*`, and that schema stops existing once `rank01` runs. There is no old-wire compatibility layer.

## 1. What shipped

### 1.1 Riot Sign-On (identity-service)

* `RiotOAuthProvider` (`provider_name = "riot"`) handles **login and link** through the existing OAuth callback and
  link paths:
  * authorize: `https://auth.riotgames.com/authorize`, `scope=openid cpid`, `redirect_uri=OAUTH_REDIRECT`;
  * token: `POST https://auth.riotgames.com/token` with HTTP Basic `client_id:client_secret`;
  * user: account-v1 `GET /riot/account/v1/accounts/me` on `https://{RIOT_ACCOUNT_CLUSTER}.api.riotgames.com`.
* The PUUID becomes `provider_user_id`. The Riot ID `gameName#tagLine` becomes `username` and `display_name`.
* `cpid` is read best-effort from `GET https://auth.riotgames.com/userinfo` into `raw_data.cpid`. It is `null` when
  that call fails or returns anything other than an object with a string `cpid`, and sign-in still succeeds. A
  missing PUUID is a 400.
* `riot` is in `OAUTH_PROVIDERS` and `VERIFIABLE_PROVIDERS`. A completed Riot sign-in or link stores a **verified**
  `riot` `players.social_account` whose `provider_user_id` is the PUUID. The provider is advertised only when
  `RIOT_OAUTH_ENABLED` is on and both credentials are set.
* The player self-link accepts a Riot connection. Its 400 detail is now *"Link Discord, Battle.net or Riot OAuth
  account before linking a player"*; the 403 detail is *"Discord, Battle.net or Riot account does not match selected
  player"*.
* Frontend:
  * `/auth/riot/login`, and Riot in the sign-in modal and the account-settings link buttons;
  * a notice beside those buttons that linking makes the rank public on OWT (`accountSettings.linked.riotNotice`);
  * the admin provider mark and the registration and identity icons (`/riot.png`).

### 1.2 Per-game mix link requirement

* `required_link_providers(discipline_code)` is Discord plus the game's `identity_provider` when that provider
  supports OAuth, else Discord alone. Overwatch is unchanged (Discord + Battle.net).
* **A LoL mix now requires Discord + Riot.** The blocker is `riot_not_linked`. Any `<provider>_not_linked` answers
  403, and Discord is reported first.
* `missing_account_links(session, auth_user_id, discipline_code)` takes the mix's game.
* The Discord bot has RU/EN copy for `riot_not_linked`, with the profile link button.
* The `player_not_linked` copy now names no provider: it said "link Battle.net" for every game.
* The site has the `mixes.self.blocker.riot_not_linked` string.

### 1.3 One `rank` schema for every game

`overwatch_rank` is renamed to `rank`. Every row of `rank.rank_snapshot`, `rank.account_state` (formerly
`battle_tag_state`) and `rank.fetch_log` carries a `discipline`, which has no server default: every writer names its
game. `battle_tag` is renamed to `handle`. `player_id_slug` is renamed to `external_id` (the OverFast slug or the Riot
PUUID; nullable). New columns:

* `account_state.region`;
* `rank_snapshot.queue` (`solo`/`flex`), `lp`, `wins` and `losses`.

`role` and `platform` are nullable, because LoL rows have neither. Section 4 lists the full migration.

* The Overwatch collector keeps its keys, queues and settings, and sets and filters `discipline='overwatch'`.
* The state, claim, pacing and admin aggregates both collectors need live in `shared/repository/ranks.py`,
  parameterised by discipline and provider.
* The tournament open-profile admission check reads only Battle.net accounts, so a Riot ID never answers for a
  BattleTag.

### 1.4 LoL ladder and native rank

* **Ladder:** `shared/disciplines/lol/ladder.py`, league-v4 tiers, **31 tiers** listed top first:

  | Tiers | `rank_value` |
  | --- | --- |
  | Challenger | 3500 and up (open top) |
  | Grandmaster | 3100–3499 |
  | Master | 2800–3099 |
  | Diamond I … Iron IV, 100 per division | Diamond I = 2700–2799 … Iron IV = 0–99 |

  * A divisional tier's value is its floor + min(LP, 99). Any apex tier's value is 2800 + LP.
  * Tier emblems are `/disciplines/lol/ranks/<tier>.png`.
  * Apex tiers have no division number, so `NativeTier.native_tier` and `NativeTierRead.native_tier` are
    `int | null`.
* **Grids:**
  * A new LoL grid is seeded with this ladder as v1, as Overwatch's is with its 45 tiers.
  * A LoL tournament, mix or clone without a LoL grid falls back to LoL's own ladder. LoL no longer answers 422
    `division_grid_required`.
  * A pin to another game's grid is still 422 `division_grid_discipline_mismatch`.
* **Native rank** (`native_ranks`, `shared/disciplines/lol/ranks.py`):
  * the source is the newest **Solo/Duo** snapshot of each Riot account;
  * an account counts only if its last successful poll is at most **30 days** old;
  * when that newest row is unranked, the account gives nothing;
  * a player gets the best value across their accounts, and that value stands for every position;
  * there is **no Flex fallback**.
* **Rank overview SQL twin:** the same read is LoL's `native_rank_rows` (`DisciplineSpec.native_rank_rows`). Its CTE
  labels the account column `handle`.

### 1.5 LoL rank collector

The collector runs in `stats-worker` as the LoL module's jobs, when the worker serves `lol`.

* **Scheduling:**
  * a 60 s tick, leader-locked on `lol_rank:scheduler:leader`;
  * each tick claims due `rank.account_state` rows (`discipline='lol'`) and publishes one fetch per account;
  * consumers run the Riot calls with no DB transaction open;
  * a fetch writes only the queue rows that changed (Solo/Duo, Flex; LP, wins, losses).
* **Defaults** (`lol.rank_collection`): collection **off**, every **6 h** (21 600 s), 50 requests/min, scope `all`,
  batch 50, 5 consecutive failures before `disabled`, backoff base 60 s.
* **Scopes:**
  * `all`: every Riot account;
  * `registrations_only`: the Riot accounts of members registered in an active LoL tournament, at priority tier 1.
* **Redis** (`lol_rank:*`):
  * pending dedup `lol_rank:fetch:pending:*`;
  * in-flight lock `lol_rank:fetch:inflight:*`;
  * global cooldown `lol_rank:cooldown`;
  * per-minute window `lol_rank:rl:<minute>`.
* **Queues**, each dead-lettering to `<name>.dlq`, declared by the module's `start_jobs`:

  | Queue | Fed by |
  | --- | --- |
  | `lol_rank_fetch` | The tick |
  | `lol_rank_fetch_priority` | Admin collect and registration approvals |
  | `lol_rank_registration_approved` | Routing key `tournament.registration.approved` |
  | `lol_rank_registration_rank_check` | Routing key `tournament.registration.rank_check_requested` |

  The two fetch queues share one channel. Its prefetch is `LOL_RANK_FETCH_WORKER_PREFETCH` (default 3).
* **The fetch:**
  1. If no PUUID is known, resolve the Riot ID to a PUUID (account-v1 `by-riot-id` on `RIOT_ACCOUNT_CLUSTER`).
  2. If no region is known, read it (`region/by-game/lol/by-puuid`).
  3. Read the current Riot ID by PUUID. This also renames the stored handle.
  4. Read league-v4 `entries/by-puuid` on the platform host.

  Only a **verified** Riot account's RSO subject is used as the PUUID.
* **Outcomes:**

  | Outcome | Effect |
  | --- | --- |
  | ok | Next poll after the interval |
  | `not_found` | Next poll after 8× the interval |
  | Transient (5xx, timeout, 401/403 from a missing or expired key) | Exponential backoff capped at 6 h; never `disabled` |
  | Permanent (an invalid Riot ID) | `disabled` after `max_consecutive_failures` |
  | 429 | Global cooldown of `Retry-After`, else 60 s |

  LoL has no `private` status.
* **Stale PUUID:** a 400 on a PUUID path re-resolves the PUUID **once in the same fetch**, by Riot ID. If that also
  fails, `external_id` and `region` are cleared.
* Fetch-log retention is 7 days (job `lol_rank_fetch_log_purge`).
* An approved registration with a Riot identity, or the registrant's own rank re-check, priority-fetches every Riot
  account of the player. The declared registration rank is never overwritten.
* The API key goes only into the `X-Riot-Token` header and never reaches a log line.

### 1.6 Rank routes, overview, registration

* **Rank routes:**
  * every `rpc.stats.rank.*` route takes `?discipline=` (default `overwatch`) and dispatches to that game's
    `collection_handlers`;
  * a game without them answers 404 `rank_collection_unsupported`;
  * `GET /api/v1/game-accounts/{id}/rank-history` (`rpc.stats.rank.game_account_history`) replaces
    `/api/v1/battle-tags/{id}/rank-history`;
  * on `GET /api/v1/users/{id}/current-ranks`, `platform` is optional;
  * LoL history is per queue, as raw change points.
* **Rank overview** (`rpc.balancer.ranks.list`):
  * the native layer is named `native` for every game;
  * Overwatch keeps the OverFast twin, and every other game uses its `native_rank_rows`;
  * rows carry `native_division` and `native_tier`.
* **Registration:**
  * for a non-Battle.net game, `native_ranks_by_registration` reads the module's `native_ranks`;
  * the autofill native stage keeps its persisted key `ow` and is offered to every game with native ranks;
  * for LoL the stage takes the Solo/Duo value, one value for composite, current and peak. The Overwatch week
    composite and `lookback_days` do not apply.

### 1.7 Frontend

* **Profile:** League's rank card shows Solo/Duo and Flex (tier and division, LP, W/L, "Unranked"), and a step chart
  of both queues over 365 days.
* **Rank service:** it always names the game. The dead `getBattleTagRankHistory` is deleted.
* **Admin › Collectors › Rank:**
  * a game switch over the games that collect ranks;
  * health, fetch log, settings, collect and re-enable all act on the selected game;
  * Pause/Resume writes the selected game's settings key: `parser.rank_collection` for Overwatch,
    `lol.rank_collection` for League.
* **Person rank panel:** uses the collector of the person's game.
* **Labels:** the collector health and history labels and the person rank-panel labels are game-neutral:
  "Accounts", "Upstream", "Auto-disabled accounts", "Re-enable all accounts", "Rank collection is down". Rank-history
  labels changed too: "By account", and "Rank history is unavailable because this account is not linked to a
  registered site account". The user docs (`/docs`, EN and RU) quote the new labels.
* **Riot legal boilerplate on `/terms` and `/privacy`** (RU/EN `riotGames` sections): "OWT isn't endorsed by Riot
  Games and doesn't reflect the views or opinions of Riot Games or anyone officially involved in producing or managing
  Riot Games properties. Riot Games, and all associated properties are trademarks or registered trademarks of Riot
  Games, Inc." The legal texts that listed Discord, Twitch and Battle.net now include Riot Games.

## 4. Migration `rank01`

`cd backend && uv run alembic upgrade head` → `rank01 (head)`. `rank01` makes these changes:

* **Schema and names.**
  * `ALTER SCHEMA overwatch_rank RENAME TO rank`;
  * `battle_tag_state` → `account_state`;
  * `battle_tag` → `handle` on all three tables;
  * `player_id_slug` → `external_id`, now nullable.
* **`discipline`.** `discipline VARCHAR(32) NOT NULL` on all three tables, with existing rows backfilled
  `'overwatch'` and the default dropped.
* **New and relaxed columns.** It adds the LoL columns, and `role` and `platform` become nullable.
* **Indexes.**
  * The series and latest-ranked indexes are rebuilt with `queue`.
  * `ix_account_state_due` on `(discipline, status, next_eligible_at, last_checked_at)` replaces
    `ix_battle_tag_state_due`.
  * `ix_battle_tag_state_priority` → `ix_account_state_priority`.
  * `ix_overwatch_rank_rank_snapshot_captured_at` → `ix_rank_rank_snapshot_captured_at`.
* **Settings seed.** It inserts the `lol.rank_collection` row with League's defaults (`enabled: false`). The insert
  is `ON CONFLICT DO NOTHING`.
* **Data rewrite of division-grid import jobs.** Every `division_grid_import_job.request_json` that has the key
  `include_ow_rank_mappings` gets it renamed to `include_native_rank_mappings`, keeping its value. This covers every
  status: pending, running, failed and completed.
  * The new job runner reads only the new key, and a failed job retries from its stored request.
  * No drain is needed: the migration rewrites the stored jobs.
  * A tournament-service image from before this release cannot process jobs after the migration, which is one
    more reason for the one-SHA deploy.
  * Idempotency keys and source fingerprints hash values, not this key, and do not change.
  * Past `admin_audit` payloads keep the old key. They are historical records that no code reads.

**Ad-hoc SQL, dashboards and backups queries** that name `overwatch_rank.*`, `battle_tag_state`, `battle_tag` or
`player_id_slug` must switch to the new names.

**Downgrade** (`alembic downgrade quota0003`) reverses the rename and the key rewrite. It also deletes:

* every non-Overwatch row of the three rank tables, which is all LoL rank data;
* the `lol.rank_collection` settings row.

An `external_id` that is NULL is restored as `replace(handle, '#', '-')`.

## 5. Configuration

| File | Key | Default | Meaning |
| --- | --- | --- | --- |
| `auth.env` | `RIOT_OAUTH_ENABLED` | `false` | Advertise Riot sign-in and link |
| `auth.env` | `RIOT_CLIENT_ID`, `RIOT_CLIENT_SECRET` | — | The RSO client's credentials |
| `auth.env` | `RIOT_ACCOUNT_CLUSTER` | `europe` | Account-v1 host for `accounts/me` (`americas`, `asia` or `europe`) |
| `stats.env` | `RIOT_API_KEY` | unset | Riot API key for the LoL collector. Unset means no `X-Riot-Token`: every fetch fails transiently and backs off |
| `stats.env` | `RIOT_ACCOUNT_CLUSTER` | `europe` | Account-v1 host for Riot ID and PUUID lookups |
| `stats.env` (optional) | `RIOT_TIMEOUT`, `RIOT_MAX_RETRIES`, `LOL_RANK_FETCH_WORKER_PREFETCH` | `10`, `3`, `3` | HTTP timeout and retries; prefetch of the LoL fetch consumers |
| `public.settings` | `lol.rank_collection` | Seeded by `rank01` | The LoL collector's runtime config (`RankCollectionConfig` shape). The admin write validator accepts any `*.rank_collection` key with that shape |

**Riot API keys.**

* A **development key expires every 24 h**: collection with one stops until the key is regenerated.
* **PUUIDs are encrypted per Riot project.** A PUUID minted under the development key does not decrypt under the
  production key, and the reverse. The same goes for the RSO client's project.
* The collector handles a 400 on a stored PUUID by re-resolving the PUUID by Riot ID once and storing the new one.
  After a key change, every account therefore re-resolves once: one extra account-v1 call per account.

## 6. Operator steps

1. Run the migration, then deploy every image from the same SHA (section 4).
2. Riot Developer Portal: on the application's **RSO client**:
   * register the redirect URI = the deployment's `OAUTH_REDIRECT` (for example
     `https://owt.craazzzyyfoxx.me/auth/callback`);
   * request scopes `openid cpid`.

   Then put the client id and secret in `auth.env` and set `RIOT_OAUTH_ENABLED=true`. The full steps are in
   [workspace-domains.md](../workspace-domains.md#riot-developer-portal-rso).
3. Set the **production** API key as `RIOT_API_KEY` in `stats.env`. PUUIDs re-resolve once whenever the key changes
   (section 5).
4. On `stats-worker`, if `STATS_DISCIPLINES` is set, it must include `lol`. When it is omitted, every installed game is
   served. The LoL queues and DLQs are declared at worker startup, so no manual RabbitMQ step is needed.
5. Enable the LoL collector in **Admin › Collectors › Rank › League of Legends › Settings**. That writes
   `lol.rank_collection.enabled`.

## 8. Deferred

* LoL history is returned as raw change points: there is no daily or hourly bucketing, and `granularity` is ignored.
  The chart draws step lines. Overwatch's `fill_rank_series` would have to move to core if League needs buckets.
* LoL `registrations_only` has no `extra_accounts_per_registration` cap, because a Riot ID is one account.
* **Wording on League's screens.** Some admin copy still says "OverFast" or "battle tag":
  * `collectors.settings.rank.*` (scope, interval and failure hints, "OverFast limits") and
    `collectors.mapping.description` *(the latter removed with the Mapping tab:
    [rank mapping removal](./2026-10-21-rank-mapping-removal.md))*;
  * `adminPeople.rank.noRank` ("No ranked battle tag yet.");
  * ~~the rank-mapping tab lists League with nothing in it~~ *(the tab is gone, same note)*;
  * the autofill dialog labels League's native stage with Overwatch wording (`rankAutofill.owValue.*`,
    `breakdown.ow*`).

  All of this works; only the wording is deferred.
* `PersonGlance` shows the first game that collects ranks only.
* The rank overview capitalises the native division, so League's tiers show upper-case (`DIAMOND`).
* The PK, unique-constraint and sequence names of `rank.account_state` keep `battle_tag_state_*`. This is cosmetic.
* Riot rate limits are enforced per minute only, with no per-second or per-method buckets; `Retry-After` covers the
  rest.
* Out of scope: champion mastery, match history, the Tournament API, match import, a Flex fallback, previous-season
  ranks, refresh tokens (`offline_access`) and summoner-icon avatars.
