# VALORANT: release note

This release adds **VALORANT** (discipline code `valorant`) as the fourth installed game. It is a base module: a
workspace can enable it, tournaments and mixes can be played in it, its agents and maps come from
[valorant-api.com](https://valorant-api.com), and its 25-tier ladder seeds division grids. **Organizers enter the
ranks.** There is no rank collector, match decoder or match import: Riot's VALORANT API needs a production key and
RSO opt-in from every player, and `val-ranked-v1` only serves the leaderboard.

One migration ships: **`valorant01`** (after `mixdraft02`). It only inserts the `catalog.discipline` row. Deploy every
backend service and the frontend from one SHA. Every wire change is additive: a fourth entry in the discipline list.

## 1. What shipped

### 1.1 The VALORANT module (`backend/shared/disciplines/valorant/`)

* **`SPEC`**: code `valorant`, name `VALORANT`, short name `VAL`, icon `assets/valorant/icon.svg`, identity provider
  `riot`. It is registered in `shared.disciplines` after Overwatch, LoL and Deadlock. `.importlinter` lists
  `shared.disciplines.valorant` in both forbidden lists.
  * Kinds: `character` "Agent" and `map` "Map". There is no mode kind. Character classes come from the valorant-api
    agent role, lower-cased: `duelist`, `initiator`, `controller`, `sentinel`.
  * Sides: `attack` (index 0) and `defense` (index 1), the `side_pick` wire index.
  * One rated dimension `agent` with one role `agent`. VALORANT ranks are per account, and the ranked queue has no
    role queue. `flex=False`: no open slot and no Full flex. The code is Deadlock's one-role code. A one-role game names
    no role in the UI, and `player` would collide with core vocabulary in the D99 literal gate.
  * Team-format preset `open_5v5` ("5v5"), with the dimension mode `off`. A roster shape is `{agent: 5}`.
  * Mixes require Discord + Riot. `account_links.required_link_providers` derives this from `identity_provider`.
* **Ladder** (`ladder.py`): 8 tiers × 3 divisions, then Radiant, listed top first (25 tiers).
  `rank_value = ((tier - 1) * 3 + division) * 100`, and each division is 100 wide:

  | Tier | `rank_value`, divisions 1 … 3 |
  | --- | --- |
  | Radiant | 2500 and up (open top) |
  | Immortal | 2200–2499 |
  | Ascendant | 1900–2199 |
  | Diamond | 1600–1899 |
  | Platinum | 1300–1599 |
  | Gold | 1000–1299 |
  | Silver | 700–999 |
  | Bronze | 400–699 |
  | Iron | 100–399 (Iron 1 = 100–199) |

  * Tier slugs are `<tier>-<division>` (`gold-2`) or `radiant`, and names are "Gold 2" and "Radiant".
  * Emblems are `/disciplines/valorant/ranks/<slug>.png`, one per division. They come from the valorant-api
    `competitivetiers` set of Episode 5 and later.
  * There is no `native_ranks` hook. A new VALORANT grid is seeded with this ladder. A tournament, mix or clone with no
    grid of its own falls back to the ladder and never answers 422 `division_grid_required`. The resolver's native
    layer is skipped.
* **Catalog sync** (`catalog_sync.py`, `POST /api/v1/admin/catalog-sync/valorant`, superuser): two reads,
  `/v1/agents?isPlayableCharacter=true` and `/v1/maps`, both before the first write. It uses no key, a 15 s timeout
  and 3 attempts.
  * Agents: the code is the slugified display name (`kay-o` for KAY/O) and the image is `displayIcon`.
  * Maps: only the bomb-site maps, those whose `tacticalDescription` is set (13 today). The image is `splash`. Team
    Deathmatch, Skirmish, the Range and Basic Training maps are skipped.
  * A new map gets `attrs.in_competitive = true`, as Overwatch's maps do. The API does not know the season's map pool,
    so organizers curate `in_competitive` in the catalog admin. A later sync never overwrites an existing row's attrs.
* **Pick/ban preset** `valorant_vct_bo1` (`pick_ban.py`, kind `map`, mode `pool`), the VCT Bo1 veto on a seven-map
  pool:
  * the steps are A-B-A-B-A-B bans, then A (the team that did not ban last) picks its starting side, then the
    decider;
  * the engine requires the `decider` to be the last step, so the side pick comes first, after the map is already
    settled;
  * the phase runs only when `best_of == 1`.

  Mixes get no ban preset: a mix plays character presets, and VALORANT declares none. The generic `map_bracket` and
  `map_slot_veto` presets stay available.

### 1.2 Frontend

* Icon `frontend/public/disciplines/valorant/icon.svg` (the V mark only) and the 25 rank emblems under
  `frontend/public/disciplines/valorant/ranks/`.
* i18n (EN/RU): side labels `pickBan.room.sides.valorant.{attack,defense}` and the preset label
  `pickBan.rules.preset.valorant_vct_bo1`.
* No `src/disciplines/valorant/` module. The registries answer `null`, so there is no rank-history card, because no
  collector exists, and no pregame character-ban board, because there is no hero preset. The map veto UI is generic.
* Site docs (`/docs`, EN and RU): VALORANT is listed among the one-role games (draft, mixes, registration), the
  ladder sizes (divisions), and the rank sources, where VALORANT has none.
* The existing Riot Games legal text on `/terms` and `/privacy` already covers VALORANT.

## 2. Wire

* `GET /api/v1/disciplines` lists a fourth row: `valorant`, `flex: false`, `short_name: "VAL"`, and capabilities
  `catalog_sync: true`, `native_ladder: true`, `native_rank_collection: false`, `match_fetch: false`,
  `achievement_conditions: false`, `analytics: false`.
* `GET /api/v1/disciplines/valorant/metadata`: roles `["agent"]`, sides `attack`/`defense`, and the 25-tier ladder.
* `/api/v1/catalog/valorant/{character,map}` answer; `/api/v1/catalog/valorant/mode` is 404.

## 3. Operator steps

1. Run `valorant01`, then deploy every image from the same SHA.
2. Publish the icon from `backend/`:
   `uv run python scripts/publish_discipline_assets.py --discipline valorant --file ../frontend/public/disciplines/valorant/icon.svg --key assets/valorant/icon.svg --publish`.
3. Sync the catalog once, as a superuser: `POST /api/v1/admin/catalog-sync/valorant`. Then set the season's map pool
   (`in_competitive`) in the catalog admin.
4. Enable VALORANT on a workspace: `PATCH /api/v1/workspaces/{id}` with `disciplines_enabled` including `valorant`.
   The workspace gets its default VALORANT grid.
5. If `STATS_DISCIPLINES` is set on `stats-worker`, list `valorant` so its ingest queue is declared. There are no
   VALORANT jobs.

## 4. Verification

* **Live catalog sync** against valorant-api.com on the test DB, with S3 stubbed and the real image downloads kept:
  13 maps and 29 agents created, 42 images fetched as `image/png`; a second run created 0 rows.
* **Migration:** `upgrade head` applies `valorant01`. `downgrade -1` on a database already holding VALORANT rows is
  refused by the foreign keys, as documented.
* **Tests:**
  * updated: `test_discipline_metadata.py` (the descriptor list), the e2e lists (`ALL_GAMES`, catalog, division
    grids, balancer config);
  * new: `test_valorant_native_rank_boundaries`;
  * passing: `test_pick_ban_rules_presets` (the preset validates for `map`/`pool`), `test_publish_discipline_assets`
    (the icon) and `test_discipline_module_boundary`.
* **Full suites:** balancer, app, tournament, analytics, stats, shared and root backend suites, and frontend vitest.
  Every failure also fails with VALORANT unregistered: the same counts in balancer (2), app (9), tournament (34),
  stats (97), shared + root (33) and frontend (1, `tournamentsList`).
* **Gates:**
  * `lint-imports`: 2 kept, 0 broken;
  * `check_discipline_literals.py`: the 27 pre-existing findings, none new;
  * `ruff check` and `ruff format --check` on the touched Python files;
  * frontend `tsc --noEmit`: clean.
* The Playwright e2e specs were edited but not run: the running e2e stack is built from an older image.

## 5. Deferred

* **Native ranks and match import.** Riot's VALORANT API needs a production key and RSO. The unofficial HenrikDev API
  needs its own key. Either one would add a `native_ranks` hook, a collector and `match_fetchers`.
* **A VCT Bo3 veto with a side per map.** A flat map pool writes every `side_pick` to game 1. Per-map sides need the
  slots mode or an engine change.
* Agent `uuid` is not stored in `attrs`. A future match decoder would need it, which takes a re-seed or a migration.
* Stats, leaderboards, achievements and analytics are not supported for VALORANT.
