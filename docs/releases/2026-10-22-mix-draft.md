# Mix rooms, stage П2 — captain draft: release note

A mix can form its lobbies' teams by a live captain draft. The host picks **Teams: Balancer / Captain draft** and a
pick clock (10–600 s, default 30) in the mix header. Each game has a default in the host's account settings, which a
new mix copies; a cloned mix keeps its source's. In draft mode a lobby's **Draft** seeds the tournament draft engine
with exactly the players a balance would seat, the two strongest as captains, the weaker picking first. **Split pool**
does it for every lobby at once, the seated set split by strength. Captains pick in snake order on the clock; a
timeout takes the captain's own list, then the best fit. Ranks are the ones the mix balance reads: the host's book, or
the effective ratings for a host in ranker mode. The last pick writes the lobby's lineup (`source: "draft"`, the
captains crowned, the balance's gap and off-role numbers). Hosts pause, resume, roll back, replace a captain, add a
waiting player or cancel. Anyone can watch the board, and the captain on the clock gets an in-browser turn alert.
Spec: `docs/superpowers/specs/2026-10-21-mix-rooms-draft-bans-design.md` §9.

## Behaviour worth knowing

- **Replace captain** moves the crown at once. Before the start any pool player may take over, and the draft re-seeds
  with the weaker captain first. During the draft a player already picked onto that team takes over; the picks stand.
  A rollback of the pick that seated the current captain is refused with 409 `rollback_frees_captain`: the host first
  crowns a player who stays on the team.
- **Away.** The policy runs only when a member's away flag really changes; saving the same value does nothing. A
  false→true change on a picked player pauses a live draft. An unpicked player leaves the pool, and the draft pauses
  only if a role can no longer be filled; the host then adds a waiting player. A return refreshes the board and never
  pauses it.
- **A completed mix draft is the lobby's lineup.** Every lifecycle move on it (start, pause, resume, cancel, rollback)
  is refused with 409 `mix_draft_completed`; the host re-forms the lobby instead.
- **Ending a draft.** Closing or cancelling the mix, or re-forming the lobby (Draft, Split pool, a balance), cancels
  its running draft. Lowering the lobby count deletes a dropped lobby's draft with the lobby. A host transfer leaves
  the draft running on the new host's ranks; picks already made keep their frozen rank in the lineup, in an all-flex
  format too. Captains, who have no pick, sit on their live rank.
- **Cards.** A drafting lobby's card shows its stage (**Draft setup** or **Draft**). In a live draft it also shows the
  elapsed time since the first pick's clock started. There is no "pick n/N" on the card.
- **Chat.** The mix's host and co-hosts always get the live draft chat, even with spectator read off. Captains write
  there too, and everyone else reads it while spectator read is on (the default). A mix draft room has no
  workspace-staff branch and no hidden-tournament gate. Replace captain re-checks the room at once: it publishes
  `chat.visibility_changed` at the unchanged setting, the gateway drops the former captain from a chat closed to
  spectators, and the board's `draft.session_updated` makes each viewer re-read their chat role, so the new captain
  gets the write controls.
- **Seat identity** is enforced in the services: a tournament seat names a registration, a mix seat a workspace member
  and no registration. A seed that breaks this gets 422 `seat_identity_invalid`. The database only requires that a
  registration or a workspace member is present (`ck_draft_player_identity`): a CHECK cannot see the session's owner,
  and legacy tournament seats have no member.
- **Seat FK and user merge.** `draft.player.workspace_member_id` is now `NO ACTION DEFERRABLE INITIALLY DEFERRED` (it
  was `SET NULL`, which would strip a mix seat of its only identity). A user merge now repoints draft seats onto the
  surviving member. It refuses with 409 `merge_draft_seat_conflict` when both accounts sit in the same running draft
  (setup to paused); cancel the draft or drop one seat, then merge.
- **The tournament draft room** (`/draft/{tournament_id}`) looks up the tournament's current session and follows it
  on the session topic. When that session completes, is cancelled or is deleted, the page asks for the tournament's
  next session once a minute.

## Deploy

Two migrations, in order after `canonical01`. **`mixdraft01`** adds `mix.custom_game.team_formation` (default `balance`,
CHECK `balance`/`draft`), `mix.custom_game.draft_pick_seconds` (default 30, CHECK 10–600) and
`balancer.user_config.formation_defaults` (`{}`). It is pure expand. **`mixdraft02`** gives `draft.session` a second
owner:

- it adds `discipline` (backfilled from the tournament), `custom_game_id` and `lobby_index`;
- it makes `tournament_id` nullable and replaces the tournament FK with a composite one that carries the workspace and
  the discipline;
- it adds the mix and lobby FKs (`ON DELETE CASCADE`), the one-owner CHECK `ck_draft_session_owner`,
  `ck_draft_session_lobby` and the partial unique index `uq_draft_session_active_lobby`, which allows one active draft
  per lobby;
- it makes `draft.player.registration_id` nullable under `ck_draft_player_identity`;
- it recreates the member FK as deferred `NO ACTION` (above).

The downgrade of `mixdraft02` deletes every mix draft.

Run both migrations, then deploy everything **from one SHA**. The board topic and the lifecycle routes change on the
wire, so the balancer-service, the gateway (routes, ACL, regenerated `schemas.json`) and the frontend must move
together. The app-service (user merge) and the tournament-service (shared mix-host check) ship the same shared draft
model. There is no new event consumer queue; the new RPC subjects come up with the balancer-service. The prefs PUT
now requires `formation_defaults`, so the previous frontend cannot save account settings until the new one is live.

## Known limits

- The merge preview does not show the draft-seat conflict; only the merge itself refuses it.
- While the followed session is over, the tournament draft room's lookup re-reads the board every 60 s per open page.
  The poll does not wait for the tab to be visible.

## Not in this release

Hero picks and Fearless (П4), Discord DMs and card states (П3), map veto. There is no "pick n/N" on the lobby cards:
a drafting card shows its stage and elapsed time, and the room shows the picks.
