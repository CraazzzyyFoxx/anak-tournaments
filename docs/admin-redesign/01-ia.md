## 2. Принципы новой IA

1. **Три контекста работы, а не шесть групп.** `Данные` (что происходит в сообществе), `Воркспейс` (как настроено сообщество), `Платформа` (суперюзер). Турниры — отдельный корневой пункт: это 90 % ежедневной работы.
2. **Глубина ≤ 3.** Сайдбар → экран → (под-таб | инспектор). Всё, что глубже, становится либо роутом с собственным URL, либо визардом.
3. **Табы — только по жизненному циклу.** Табы хаба = фазы турнира (Overview → Registration → Teams → Bracket → Matches). Конфигурация не таб, а секция Settings.
4. **Один шаблон на один тип задачи.** 7 шаблонов экранов (§4). Любой экран обязан быть экземпляром одного из них.
5. **Состояние явное, не спрятанное.** Draft показывает свою фазу степпером; Divisions — линейный поток «Библиотека → Редактор | Импорт → Конфликты»; ни один экран не меняет содержимое молча по статусу.
6. **URL хранит всё.** Активный таб, выбранный объект инспектора, фильтры — в query. Ссылка из Discord открывает тот же экран.

## 3. Навигация

### 3.1 Сайдбар (13 пунктов вместо 24)

```
Dashboard
Tournaments
── DATA ──────────────────
People          ← /admin/users + /admin/players  (identities; участия — внутри карточки человека)
Teams           ← /admin/teams
Matches         ← /admin/encounters + /admin/match-reports + /admin/matches + /admin/standings
Achievements    ← /admin/achievements
── WORKSPACE ─────────────
Settings        ← workspaces/[id] (текущий) + divisions + balancer + sub-roles + subscriptions?tab=providers
Members         ← /admin/workspaces/members
── PLATFORM (superuser / global) ──
Game content    ← heroes + maps + gamemodes + aliases (как «Unresolved names», с бейджем очереди)
Collectors      ← rank + subscriptions + streams
Access          ← access/* (Accounts · Roles · Permissions · API keys · OAuth · Sessions)
Workspaces      ← /admin/workspaces (детали воркспейса = тот же Settings-хаб, скоуп по id)
Audit log       ← /admin/audit
```

Группа PLATFORM скрыта целиком, если пользователю недоступен ни один её пункт. Command palette остаётся (страницы); поиск сущностей — фаза 2 (нужен backend search endpoint).

## 4. Шаблоны экранов

Каждый экран — экземпляр ровно одного шаблона. Это и есть «интуитивная компоновка»: пользователь узнаёт форму экрана до чтения заголовка.

| # | Шаблон | Структура | Где применяется |
|---|---|---|---|
| T1 | **Dashboard** | Приветствие + одно действие → KPI-полоса → 2 колонки: «работа» / «внимание» | `/admin` |
| T2 | **Browser** | Header → Filter bar (search + chips + saved filters) → Table (kebab-меню действий всегда видно) → **Inspector** (правый sheet, `?id=`) с кнопкой «Open page», если есть роут | People, Teams, Matches (все 5 видов), Achievements, Members, Content-каталоги, Access-списки, Audit, Sessions |
| T3 | **Hub** | Entity header (имя, статус, метрики, 1–2 действия) → Tabs (URL) → опционально Sub-tabs (URL) → тело | Турнир, Person, Team |
| T4 | **Master-detail** | Список слева (сортируемый, «+ Add») → редактор справа; деструктивные действия в меню, один параметризуемый confirm | Bracket (stages), Pre-game phase (scopes), Divisions library, Roles |
| T5 | **Settings** | Вертикальная навигация секций слева → форма секции → sticky save-bar при dirty | Workspace Settings, Tournament Settings, Workspace detail (superuser), Collector settings |
| T6 | **Wizard** | Step rail → контент шага → footer (Back · Save draft · Continue) | New tournament, Draft setup, Divisions import, Challonge sync |
| T7 | **Control room** | Status hero (фаза, таймер, соединение) → главная зона (текущее действие + lifecycle-кнопки) → правая колонка (presence, feasibility) | Draft live, Logs processing (mini) |

Правила, общие для всех шаблонов:

- **Детали строки:** ≤ 6 полей на редактирование → диалог; просмотр/расследование → Inspector-sheet; редактируемая и шарабельная сущность → роут. Дефолт для T2 — Inspector.
- **Действия строки:** всегда видимое kebab-меню `⋯`; иконки edit/delete только в Inspector. Удаляем двойную конвенцию actions-колонки.
- **Фильтры:** только chips (`AdminFilterChips`) + search в одном Filter bar; `Select` в тулбаре запрещён. Состояние в URL.
- **Табы:** одна реализация (routed tabs с `aria-current`), под-табы — вторая строка того же компонента. ToggleGroup/pill-nav уходят.
- **Диалоги на экран ≤ 3:** create/edit (`EntityFormDialog`), confirm (`DeleteConfirmDialog` с параметром intent), и максимум один доменный.
- **Empty / error / filtered-empty** — `PageStateCard`, три состояния различимы.

## 5. Хаб турнира

```
Header: name · status pill · dates · counts(teams/encounters/standings) · [Open analytics] [Status ▾]
Tabs:   Overview | Registration | Teams | Bracket | Matches | Settings
```

| Таб | Под-табы | Что внутри | Шаблон |
|---|---|---|---|
| Overview | — | Next action hero → PhaseStepper → LifecycleChecklist (6 фаз, deep-links) → 3 StatTile | — |
| Registration | Entries · Form · Sheets feed · Rank autofill | Entries: RegistrationTeamsCard (если formation=registration) + таблица с Inspector | T2 |
| Teams | Roster · Draft (только formation=draft) | Roster: команды + Challonge sync (wizard). Draft: степпер Setup → Ready → Live → Done; Setup = T6, Live = T7 | T2 / T6 / T7 |
| Bracket | — | Список стадий слева, редактор стадии справа (General · Seeding · Tiebreakers · Best-of · Items); `?stage=ID` | T4 |
| Matches | Encounters · Standings · Reports · Parsed maps · Logs | Каждый — Browser с Inspector; scope-фильтр по стадии общий для всех видов | T2 |
| Settings | секции: General · Rules & scoring · Schedule · Roster shape · Pre-game phase · Match report form · Links · Integrations · Preview access · Danger zone | Pre-game phase внутри — T4 (scope-дерево слева, конфиг справа) | T5 |

Тонкости:
- Draft-live баннер на Overview остаётся (ссылка в Teams › Draft).
- Sub-tab bar Registration переиспользует компонент sub-tab bar из Matches (сегодня их два).
- Логи: полоса прогресса очереди в Overview (мини T7), полный экран — Matches › Logs.

## 7. Что не трогаем

- Backend-контракты и query-keys — редизайн только фронта.
- Логику permission gating — она переезжает вместе с экранами.
- `AdminDataTable` как движок — меняется только его тулбар (chips + search) и колонка действий.
- Public site (`(site)/*`).

## 8. Открытые вопросы к утверждению

1. **People vs Players.** Убрать кросс-турнирную таблицу `/admin/players` в пользу «участий» в карточке человека — или оставить как вид `Matches?view=players`? Предложение: убрать; фильтр по турниру уже покрыт хабом.
2. **Aliases в Game content.** Скаут предлагает вынести к data-quality (Audit). Предложение: оставить рядом с каталогами как «Unresolved names» с бейджем — очередь работает *с* каталогами.
3. **Standings как под-таб Matches** или отдельный таб хаба? Предложение: под-таб — это выход результатов, не отдельная фаза.
4. **Порядок Platform-пунктов** и нужен ли `Workspaces` рядом с `Settings` для суперюзера (один и тот же T5-хаб).


## 9. Референс: «Divisions Admin» от Claude Design

Файл `Divisions Admin (offline).html` в корне репо. Проверен против `backend/shared/models/division_grid/division_grid.py` — модель макета (Grid → Version со статусами → Tier с `ow_rank_min/max`; `Mapping` между версиями с `rules`, `is_complete`; `ImportJob`) совпадает с бэкендом один в один.

**Берём** (вошло в F11 / F12 / F12b):

- Ладдер как основной инструмент редактирования вместо таблицы диапазонов; инвариант непрерывности полос — конструкцией UI.
- Полоса версий с статусами и счётчиками турниров; поясняющий абзац про иммутабельность версий и маппинги.
- Mappings как постоянный вид редактора (AUTO 100 % / 67 %, «N to resolve», split → ручной выбор `is_primary`), а не шаг импорта после ошибки.
- Панель Impact (сколько игроков сменит дивизию, какие турниры читают какие версии) и pre-flight «Ready to publish?».
- Undo-стек, Discard draft, «borrows crest» у новой дивизии, «Split the widest», разделение Publish (иммутабельно) и Activate.
- Визуальный язык уже Editorial Tactical (Inter / Onest / JetBrains Mono, одна бирюза, mono-uppercase лейблы) — прямой референс для этапа 2.

**Меняем**:

- Макет — отдельная страница с тремя колонками + правая панель; у нас редактор живёт под Workspace Settings, поэтому обзор (T5) и редактор (полноэкранный роут) разделены, иначе 4 колонки.
- Колонка ладдера в макете растягивает страницу до ~2000px и скроллится вместе с таблицей — у нас свой scroll-контейнер.
- Клетка «PLAYERS · 3 RENAMED / BAND MOVED» смешивает две величины — разносим в Players и «vs v3».
- Правая панель на <1280px становится табом «Impact» рядом с Mappings.
- Сокращения полос `UL1–UL3`, `GR5–MA2` — только в компактных местах (Mappings), в основной таблице полные имена рангов.
- Макет подразумевает один грид на воркспейс; модель допускает несколько — селектор грида появляется над полосой версий только когда гридов > 1.
